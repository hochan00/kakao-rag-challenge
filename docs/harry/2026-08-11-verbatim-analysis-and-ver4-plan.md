# 원문 복사 가설 검증과 ver4 설계 (2026-08-11)

## 1. 새 순위 — 12팀 ver2가 1위로 올라섬

| 팀 | 총점 | 키팩트 F1 | 판정 |
| --- | ---: | ---: | ---: |
| **12 (ver2)** | **91.174** | 0.7508 | **97.30** |
| 17 | 90.733 | 0.7669 | 95.45 |
| 14 (ver2) | 89.500 | 0.7275 | 95.35 |

## 2. 가설 검증: "원문을 그대로 옮기면 키팩트를 더 받는가" → **맞다**

verbatim 지표 = 답변 문자 중 정답 조문 원문과 15자 이상 연속 일치하는 구간의 비율.

| 팀 | verbatim | 키팩트 F1 |
| --- | ---: | ---: |
| 12v2 | **0.970** | 0.7508 |
| 14v2 | 0.872 | 0.7275 |
| 17 | 0.753 | 0.7669 |
| 14v3 | **0.613** | 0.657(근사) |

- 문항 단위 상관(3팀×10문항): **r = +0.38**, recall과의 상관도 +0.38 — 원문 복사는 "빠짐없음"을 통해 작동한다.
- 문항별 승자 10개 중 7개가 verbatim ≥ 0.85.
- 12v2는 거의 순수 추출(0.970)인데 **판정 97.30으로 전체 1위** — 원문 복사가 judge를 깎지 않는다.
- 14v3의 verbatim 0.613(최저)이 F1 하락 예측(−2.30점)의 실체다: 조 명칭 인용 + 모델 재서술("여러분"→"이용자들이")이 원문 일치를 깨뜨렸다.

단, verbatim만으로는 부족하다. 17팀은 verbatim 0.753으로도 F1 1위인데 **관련 문장을 더 넓게 담았기 때문**(coverage)이고, 12v2의 P02(F1 0.60)는 무관한 앞 문단까지 복사해 정밀도를 잃었다. 결론: **정확한 문장을 + 전부 + 원문 그대로**.

- 마커(①, N.) 노출: 승자 중 유/무 혼재라 F1에는 중립이지만, 17팀 P10 clarity 7점(마커 노출 지적)이므로 제거가 안전.

## 3. 추출식 상한 실측

정답 조문의 문장들을 그리디로 골라 붙였을 때 도달 가능한 키팩트 F1(단어집합 근사, 17팀 데이터로 오차 ±0.007 검증된 산식):

```
평균 상한 0.8466  →  배점 환산 25.40점  (우리 현재 21.83점, +3.57점 여지)
문항별: P08 0.9474(2문장), P05 0.9130(1문장), P07 0.5570(키팩트가 여러 조에 분산된 유일한 예외)
```

## 4. 기반 파일 선택: **ver3 (src/result_generator.ipynb)**

비공개 30문항 기준으로 ver2는 실격 위험이 있다.

| 근거 | ver2 | ver3 |
| --- | --- | --- |
| OOM 잠재 결함 (최악 조합 10271자 = 2973 MiB) | **있음** | 수정됨 (조문당 1600자 예산) |
| 긴 조문에서 질문 관련 항만 남기는 다듬기 | 없음 | 있음 (동적) |
| 1순위 오답 시 MRR 부분 점수 (retrieved 4개) | 없음 | 있음 |
| 검색 랭킹 코어 (하이브리드 RRF) | 동일 | 동일 |

검색 랭킹은 동일하므로 "검색 효율"의 실질 차이는 **실행 생존성과 근거 구성**이고, 둘 다 ver3이 우위다.

## 5. ver4 설계 — 생성기의 역할을 "작성자"에서 "선택자"로

시스템 프롬프트 수정만으로는 재서술 습관을 못 막는다(ver3에서 실증). 구조를 바꾼다.

```
[현재]  근거 조문 4개 → LLM이 답변 문장을 새로 씀 → 재서술·인용 드리프트
[ver4]  근거 조문을 문장 단위로 번호 매김 [S1-1] [S1-2] …
        → LLM은 JSON으로 선택만: {"direct": "아니오.", "pick": ["S1-2","S1-3"], "used": ["S1"]}
        → 코드가 원문 문장을 조문 순서대로 이어붙여 답변 조립 (verbatim = 1.0 보장)
```

- **동적 맥락 융합**: 문항마다 다른 문장 집합이 선택된다. 문장 후보 자체가 질문에 따라 달라진다(기존 trim의 항 점수 재사용).
- **정적 모델**: LLM 가중치는 그대로, 역할만 판별로 축소 — 작은 모델이 더 잘하는 과제다.
- direct 필드는 예/아니오·수치형 질문에서만 채우게 해 P08형(accuracy 가중 0.40) 방어.
- 조립 시 마커 제거 + `。` 정규화 유지. 조 명칭 전면 인용은 하지 않는다(측정 −1.63점).
- 선택 지시는 "질문과 관련된 문장은 하나도 빠뜨리지 말 것"(17팀의 coverage 우위 이식).
- JSON 파싱 실패 폴백: 1순위 조문에서 항 점수 상위 문장 추출 — **LLM 없이도 답이 나오는 결정론적 경로**라 실행 실패·형식 붕괴에 강하다.

기대치: 상한 25.40점, 12v2 스타일 실증치 0.75~0.77 구간(+1.2~1.7점). 판정 리스크는 12v2(97.30)가 반증.
