# ver4 작업 계획 — 추출식 답변 조립 (2026-08-11)

배경 분석과 근거 수치는 [원문 복사 가설 검증](2026-08-11-verbatim-analysis-and-ver4-plan.md), 직전 회차 변경 내역은 [ver2 → ver3 변경사항](2026-08-11-ver2-to-ver3-changes.md) 참고.

## 1. 한 줄 요약

**생성 모델의 역할을 "답변 작성자"에서 "원문 문장 선택자"로 바꾼다.** 답변 문장은 코드가 약관 원문에서 그대로 이어붙여 조립하므로, 재서술로 인한 키팩트 손실이 구조적으로 불가능해진다.

## 2. 왜 프롬프트 수정이 아닌 구조 변경인가

ver2·ver3에서 "조문의 표현을 원문 그대로 옮긴다"를 시스템 프롬프트로 지시했으나 모델은 계속 재서술했다. ver3 P09가 그 증거다.

```
원문/키팩트: 본 라이선스는 여러분이 서비스의 사용을 중단하거나 … 존속하게 됩니다
ver3 실제  : 카카오 통합 약관 제10조에 따르면, 이용자들이 서비스 사용을 중단하거나 …
             이용자들이 회사에게 부여한 라이선스는 계속해서 존속합니다
             → F1 0.8333 → 0.4878
```

"여러분"이 "이용자들이"로, "본 라이선스"가 "부여한 라이선스"로 바뀌었다. 지시로 막지 못한 것을 **구조로 막는다.**

이는 특강의 두 문장에 대한 응답이기도 하다. 프롬프트 문구 튜닝은 같은 봉우리 위에서의 이동(지역 극대)이고, 역할 재정의는 봉우리 자체를 옮기는 변경이다. 그리고 **정적 모델**(Qwen 가중치 불변, 역할만 판별로 축소)과 **동적 맥락**(문항마다 후보 문장 집합이 달라짐)의 융합에 해당한다.

## 3. 근거 수치

| 측정 | 값 | 출처 |
| --- | ---: | --- |
| verbatim ↔ 키팩트 F1 상관 | r = +0.38 (n=30) | 3팀 × 10문항 |
| 1위 12팀 ver2의 verbatim | 0.970 | 판정도 97.30으로 전체 1위 |
| ver3(현재)의 verbatim | 0.613 | 최저 |
| **추출식 상한 F1** | **0.8466 → 25.40점** | 현재 21.83점, **+3.57점 여지** |

12팀이 거의 순수 추출(0.970)로 판정 1위(97.30)를 받았다는 사실이 "원문 복사는 judge를 깎는다"는 우려의 반증이다.

## 4. 문장 분리기 검증 (실측 완료)

```python
_MARKER = re.compile(r"^\s*(?:[①-⑮]|\d+\.)\s*")
_SPLIT  = re.compile(r"(?<=\.)\s+|\n")
```

| 항목 | 결과 |
| --- | --- |
| 72개 조문 → 총 문장 | 607개 |
| 조문당 문장 수 | 평균 8.4 / 중앙 6 / 최대 42 |
| 문장 길이 | 평균 77자 / 중앙 67자 / 최대 275자 |
| 500자 초과(미분할 의심) | **0건** |

감점 문항에서의 정렬이 특히 좋다.

- **P08** — 조문이 정확히 2문장으로 쪼개지고 키팩트 2개와 1:1 대응. 12팀은 이 둘을 그대로 옮겨 F1 0.9545를 받았다.
- **P02** — S-10 한 문장이 "복구 노력"과 "2시간 이상 지연 시 공지" 두 키팩트를 모두 포함.
- **P09** — S-6이 키팩트 1, S-2가 키팩트 2("전 세계적이고 영구적인")에 대응.

> 미완: 문장 이어붙이기의 무손실 여부를 자동 검증하는 assert는 아직 없다. 구현 시 마커 제거분만 차이나는지 확인하는 테스트를 포함한다.

## 5. 설계

### 5.1 근거 제시 — 문장 단위 ID 부여

```
[S1] 카카오 통합 약관 제3조(약관 외 준칙)
  [S1-1] 본 약관에 규정되지 않은 사항에 대해서는 관련법령 또는 회사가 정한 서비스의 개별 이용약관, 운영정책 및 규칙 등(이하 '세부지침')의 규정에 따릅니다.
  [S1-2] 또한 본 약관과 세부지침의 내용이 충돌할 경우 세부지침에 따릅니다.
```

문장 후보는 ver3의 `EVIDENCE_CHAR_BUDGET`(조문당 1600자) 다듬기를 통과한 텍스트에서 만든다. 조문당 최대 약 21문장, 4개 조문 합쳐 최대 약 84문장.

### 5.2 모델 출력 — 선택만

```json
{"direct": "아니오.", "pick": ["S1-2", "S1-1"], "used": ["S1"]}
```

- `direct` — 예/아니오나 수치를 직접 묻는 질문에만 채운다. 비어 있어도 된다. accuracy(가중치 0.40) 방어용이며 P08형 함정을 겨냥한다.
- `pick` — 답변에 쓸 원문 문장 ID. **질문과 관련된 문장은 하나도 빠뜨리지 말 것**을 지시한다(17팀의 coverage 우위 이식).
- `used` — retrieved에 남길 조문 ID.

### 5.3 조립 — 코드가 수행

```
answer = (direct + " " if direct else "") + " ".join(원문 문장들)
```

- 문장은 **조문 순서 → 문장 순서**로 정렬해 이어붙인다(모델이 고른 순서가 아니라).
- 마커(①, N.) 제거 상태로 저장돼 있으므로 17팀 P10의 clarity 감점(마커 노출) 재발 없음.
- `_normalize_answer`(CJK 문장부호)와 `_CROSS_REF`(상호참조 제거) 후처리는 그대로 적용.
- 조 명칭 전면 인용은 **하지 않는다** (측정 −1.63점).
- `pick` 상한 6문장 — 정밀도 방어. 12팀 P02가 무관한 앞 문단까지 복사해 F1 0.60에 그친 사례가 근거.

### 5.4 부수 효과 — 지연·메모리 동시 개선

출력이 한국어 문장(약 110토큰)에서 ID 목록 JSON(약 40토큰)으로 줄어든다.

- `max_new_tokens` 768 → **약 200**으로 하향 가능
- ver3 실측 p50 23.8s / p95 38.6s에서 상당폭 하락 예상
- 생성 길이가 줄면 KV 캐시도 줄어 OOM 여유가 더 확보된다

### 5.5 폴백 — LLM 없이도 답이 나오는 경로

JSON 파싱 실패 시 1순위 조문에서 **항 점수 상위 문장 2~3개**를 그대로 조립해 반환한다. ver3의 `unit_score`를 문장 단위로 확장해 재사용한다. 생성이 형식을 깨거나 실패해도 빈 답변이 나가지 않으므로 실행 실패 위험이 줄어든다.

## 6. 기반 파일: **ver3** (`src/result_generator.ipynb`)

| 근거 | ver2 | ver3 |
| --- | --- | --- |
| OOM 잠재 결함 (최악 10271자 = 2973 MiB) | **있음** | 수정됨 |
| 긴 조문에서 질문 관련 항만 남기는 다듬기 | 없음 | 있음 |
| 1순위 오답 시 MRR 부분 점수 (retrieved 4개) | 없음 | 있음 |
| 검색 랭킹 코어 (하이브리드 RRF) | 동일 | 동일 |

검색 랭킹이 동일하므로 비공개 30문항에서의 실질 차이는 **실행 생존성과 근거 구성**이며 둘 다 ver3 우위다.

## 7. 구현 단계

1. `split_sentences()` + 무손실 assert 추가
2. `HybridRetriever`가 조문과 함께 문장 목록·문장별 점수를 반환하도록 확장 (`_units_of`, `unit_score` 재사용)
3. `AnswerGenerator.generate()` 프롬프트를 선택형으로 교체, `max_new_tokens` 200으로 하향
4. `_parse_selection()` — `direct`/`pick`/`used` 파싱, ID 유효성 검사, 6문장 상한
5. `assemble_answer()` — 조문·문장 순서 정렬 후 조립, 기존 후처리 2종 적용
6. 폴백 경로 구현
7. ver3에서 유지: 스냅샷·검색·`EVIDENCE_CHAR_BUDGET`·GPU 메모리 확보 3종·`retrieved` 4개 채움

## 8. 검증 순서 — 회차를 쓰기 전에

1. **오프라인 (회차 소모 0)** — 골드 조문으로 조립 로직 시뮬레이션. 이미 상한 0.8466 확인. 다음은 실제 검색 결과 기준으로 재측정.
2. **오프라인 채점기 모듈화** — 지금까지의 측정 스크립트가 임시 디렉터리에만 있어 재사용이 불가능하다. 키팩트 F1(단어 집합 근사, 17팀 데이터로 오차 ±0.007 검증)과 판정 4축 가중 점수(acc .40 / grd .25 / cmp .20 / clr .15, 20문항 오차 0)를 계산하는 모듈을 저장소에 만든다. **이것이 남은 회차를 아끼는 유일한 수단이다.**
3. **Colab 1회 실행** — 형식·지연·OOM 확인 후 4회차 신청.

## 9. 위험과 대응

## 10. 기대치

추출 상한 25.40점(현재 21.83점). 12팀·17팀 실증 구간 0.75~0.77을 달성하면 **+1.2~1.7점**, 상한에 근접하면 그 이상. MRR 20점과 판정은 현 수준 유지가 목표다.
