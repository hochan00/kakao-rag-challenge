# ver2 → ver3 변경사항 (2026-08-11)

3회차는 **OOM 방어 검증이 목적**이다. 단일 변수 실험이 아니며 생성 품질 변경이 다수 섞여 있다.

## 코드 변경 6건

| # | 변경 | 이유 / 예상 효과 |
| --- | --- | --- |
| 1 | 시스템 프롬프트 4규칙 → 9규칙 | 직접 답변 서두, 조 명칭 인용, 키팩트 누락 방지, 무관 내용 복사 금지 |
| 2 | 합성 1-shot 예시 추가 (가상 조문) | 답변 형식 시연. 공개 문항과 무관해 과적합 없음 |
| 3 | `max_new_tokens` 512 → 768 | 답변이 길어져도 열거형이 잘리지 않게 |
| 4 | `_normalize_answer` 후처리 신규 | 중국어식 마침표 `。` 제거 → clarity 감점 회수 (**실측 4건 → 0건**) |
| 5 | `retrieved` 항상 4개로 채움 | 비공개 문항에서 1순위 오답 시 MRR 부분 점수 보존 |
| 6 | **`EVIDENCE_CHAR_BUDGET = 1600`** + GPU 메모리 확보 3종 | **OOM 수정.** 아래 별도 항목 |

### 6번 상세 — 이번 회차의 본래 목적

- P07이 CUDA OOM으로 3회 반복 전부 실패했다. 근거 조문 7027자 중 3·4순위 두 조문이 83%(3482자 + 2361자)를 차지했고, 어텐션 버퍼는 길이의 **제곱**으로 커진다.
- 최악 조합은 10271자(2973 MiB)로 **ver1·ver2 코드에도 있던 잠재 결함**이다. 공개 10문항이 우연히 그 조합을 피했을 뿐이다.
- 조문당 1600자 예산을 넘으면 질문과 관련된 항만 남긴다. 최고 점수 항은 예산 초과여도 항상 포함해 정답 문장이 잘리지 않는다.
- 함께 적용: `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`, 인덱스 구축 후 bge-m3를 CPU로 이동(약 2.3GB 확보), 생성 직후 KV 캐시 반환.
- **결과: P07 성공, `fail=0`. OOM 수정 검증 완료.**

## 예측 — 점수는 떨어질 가능성이 높다

역산 F1 산식(단어 집합 F1)을 **17팀 데이터로 외부 검증**했고 오차가 ±0.007이었다.

```
ver2 근사 F1  0.7339   (실제 0.7275)
ver3 근사 F1  0.6571   → 배점 환산 -2.30점
```

**10문항 중 9개 하락.** 원인은 규칙 2(조 명칭 전면 인용)다. ver3 답변에서 인용구만 제거하면 0.6571 → 0.7116으로 **+1.63점 회복**된다.

가장 큰 하락 P09 (0.8333 → 0.4878):

```
ver2: 본 라이선스는 여러분이 서비스의 사용을 중단하거나 … 존속하게 됩니다
ver3: 카카오 통합 약관 제10조에 따르면, 이용자들이 서비스 사용을 중단하거나 …
      이용자들이 회사에게 부여한 라이선스는 계속해서 존속합니다
```

인용구가 붙은 데다 원문 표현("여러분", "본 라이선스")이 모델 표현으로 바뀌었다. 키팩트는 약관 원문 그대로라 이중 손해다.

`。` 제거로 clarity가 +0.75점 회복되므로 **순효과 약 −1.5점, 예상 총점 88 내외**로 본다.

## 참고 — 1위 17팀(90.733) 대비

격차 1.233점 중 **96%가 키팩트 F1**이고 판정은 사실상 동점(+0.05)이다. 17팀은 원문을 길게 복사해 F1을 벌고 판정에서 조금 잃는 전략이다(P08 판정 71.5로 우리 82.0보다 나쁨). 우리는 정반대였다. 4축 합계로 보면 우리가 accuracy +3·clarity +3, 17팀이 grounding +3·**completeness +5**.
