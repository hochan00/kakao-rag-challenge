# ver5 계획 — ver2 기준 최소 개입 (2026-08-11)

기준 파일 `src/result_generator_ver2.ipynb` (89.500점). ver3(예상 88)에서 후퇴한 이유가 규명됐으므로 ver2로 되돌아가 **측정된 것만** 얹는다.

## 1. 반증된 두 가설 — 무엇을 하지 말아야 하는가

### 1-1. 규칙을 늘리면 좋아진다 → 반증

ver3에서 규칙을 4개 → 9개로 늘렸고 총점은 하락 예측(−1.5점)이다. 원인은 규칙 하나(조 명칭 전면 인용)였다.

```
전면 인용의 F1 손해   -1.714점   (10문항 전부 하락)
grounding 회수        +0.375점   (P08 한 문항뿐)
순효과                -1.34점
```

**교훈:** 규칙은 각각 측정하기 전에는 이득인지 알 수 없다. ver5는 규칙을 4개 → 6개로만 늘리고, **인용 규칙은 넣지 않는다.**

### 1-2. 문장 선택기가 LLM 자유 작성보다 낫다 → 반증 (신규 실측)

ver4 계획의 핵심이던 "문장 단위 선택 후 조립"을, 골드 키팩트를 보지 않고 질문 유사도만으로 시뮬레이션했다.

| 전략 | 평균 F1 | 배점 30 환산 |
| --- | ---: | ---: |
| **ver2 실제 (LLM 자유 작성)** | **0.7275** | **21.82** |
| 문장선택 top-2 | 0.6636 | 19.91 |
| 문장선택 top-3 | 0.5704 | 17.11 |
| 문장선택 top-4 | 0.5193 | 15.58 |
| 문장선택 top-6 | 0.4159 | 12.48 |

문항별로 보면 이유가 분명하다.

- **P08**: 선택기 0.9474 vs ver2 0.4286 — ver2가 한 문장만 쓰고 끝낸 문항에서 선택기가 압승
- **P03**: 선택기 0.2449 vs ver2 0.8732 — 5가지 열거 문항은 6문장이 필요한데 top-2로는 불가능
- **P01·P05**: ver2가 이미 한 문장으로 정답을 맞힌 문항에서 선택기가 군더더기를 붙여 하락

**고정 개수 선택은 틀렸다.** 필요한 문장 수가 문항마다 2개에서 6개까지 다르고, 그 판단이 바로 LLM이 하는 일이다. 선택 구조 자체를 버리는 것이 아니라, **고정 N을 강요하는 설계를 버린다.** ver5는 LLM에게 "관련된 문장을 모두"라고 지시하되 개수는 맡긴다.

## 2. 확정 개선 — 전부 ver2 실제 답변에서 측정

### 2-1. 후처리 3종 (결정론적, 모델 무관)

| 후처리 | 근사 F1 | 대비 | 배점 환산 |
| --- | ---: | ---: | ---: |
| ver2 원본 | 0.7339 | — | — |
| + 상호참조 제거 | 0.7469 | +0.0130 | **+0.39점** |
| + 항 마커 제거 | 0.7360 | +0.0022 | +0.06점 |
| + CJK 문장부호 | 0.7339 | 0 | 0 (F1엔 무영향) |
| **셋 전부** | **0.7490** | **+0.0152** | **+0.45점** |

CJK 문장부호(`。`)는 F1을 바꾸지 않지만 **clarity를 깎는다.** ver2의 clarity 부족분 10축점 = **+0.750점** 회수 가능하며, `。`는 P06·P08·P09·P10 네 문항에 있다.

가장 큰 개별 효과는 P04다: `제1항 및 제2항의 규정에 의하여` 제거로 0.8571 → 0.9474.

**후처리 합계 예상: +1.20점**

### 2-2. 프롬프트 4규칙 → 6규칙

추가하는 두 규칙은 ver2의 최대 손실인 **재현율**을 겨냥한다. ver2의 recall이 0.5 이하인 문항은 P02·P07·P08·P09 네 개다.

| 신규 규칙 | 근거 |
| --- | --- |
| 관련된 문장이 여러 개면 **모두** 옮긴다. 하나만 옮기고 끝내지 않는다 | 11팀(97.455)의 recall은 10문항 전부 1.00. ver2는 4문항이 0.5 이하 |
| 예/아니오로 답할 수 있으면 '네'/'아니오'로 시작한다 | P08 골드 키팩트가 문자 그대로 "아니오."로 시작. accuracy 가중치 0.40으로 최대 |

기존 규칙에 "**원문 그대로 옮겨 붙인다**"를 강화한다. verbatim(원문 연속일치 비율)과 F1의 상관이 r = +0.38이고, 1위 11팀 0.835 / 12팀 0.970 대 ver3 0.613이다.

**넣지 않는 것:** 조 명칭 인용 규칙(−1.34점), 1-shot 예시(ver3에서 효과 미분리), 상호참조 금지 규칙(후처리가 확실히 처리하므로 프롬프트 낭비).

### 2-3. 근거 제시에서 항 마커 선제거

모델에게 주는 조문 텍스트에서 `①`, `1.` 마커를 미리 지운다. 없는 것은 복사할 수 없다. 17팀이 P10에서 마커 노출로 clarity 7점을 받은 사례가 근거다.

### 2-4. OOM 방어 (ver3에서 검증 완료, 필수)

ver2에는 **실격급 잠재 결함**이 있다. 근거 조문 길이가 무제한이라 어텐션 버퍼가 길이의 제곱으로 커진다.

```
P07 근거 7027자 → 1499 MiB   (ver3 실행에서 실제 OOM 발생)
최악 조합 10271자 → 2973 MiB  (공개 10문항이 우연히 피했을 뿐)
```

ver3에서 검증된 4종을 그대로 이식한다. 조문당 1600자 예산(초과 시 질문 관련 항만 유지, 최고 점수 항은 항상 포함), `expandable_segments`, 인덱스 구축 후 bge-m3를 CPU로 이동, 생성 후 KV 캐시 반환. **ver3 실행에서 P07 성공·fail=0으로 확인됨.**
