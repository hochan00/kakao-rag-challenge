# 약관 RAG 문서화 및 Git 동기화 설계

## 목적

카카오 약관 QA 결과기가 새 Colab T4 런타임에서 재현 가능하게 동작하도록, 약관 데이터의 특성과 인덱싱 전략을 팀 공통 문서로 남긴다. 팀원은 안전한 스크립트로 현재 작업 브랜치의 원격 변경을 가져온다.

## 저장 규칙

- 팀 전체가 함께 따르는 기준과 공통 도구: `docs/common/`, `scripts/`
- Harry의 개인 조사·실험 기록: `docs/harry/`
- Hayes의 개인 조사·실험 기록: `docs/hayes/`
- 공통 문서를 개인 폴더에 복제하지 않는다. 개인 실험 결과가 공통 결정으로 채택될 때만 `docs/common/`에 요약한다.

## 산출물

| `docs/common/TERMS_DATA_CHARACTERISTICS.md` | 4개 약관의 버전·계층·질문/인용 특성 및 공개 평가셋 해석 |

## 데이터·검색 설계

약관은 런타임 웹 스크래핑 대신 시행일이 고정된 전문 스냅샷으로 포함한다. `문서명`, `시행일`, `공식 URL`, `조 번호`, `항/호 번호`, `본문`을 메타데이터로 유지한다.

파싱은 조 제목을 기준으로 결정론적으로 수행한다. 검색 단위는 조문이며, 길이가 긴 조문만 같은 조 번호를 유지한 보조 청크로 분할한다. `retrieved`에는 보조 청크가 아니라 실제 근거 조문의 고정 문서명과 정수 조 번호만 최대 4개를 반환한다.

소규모 말뭉치이므로 인프라형 벡터 DB는 사용하지 않는다. 다국어 E5 dense 벡터의 정확 최근접 검색(FAISS `IndexFlatIP`)과 한국어 문자 n-gram 희소 검색을 Reciprocal Rank Fusion으로 결합한다. 후보 수가 작으므로 근거 조문을 정렬하고, 생성 모델에는 상위 2~4개 조문과 메타데이터만 전달한다.

## 평가 기준

`data/gold_questions_public10.json`의 `gold_articles`를 사용해 문서·조문 단위 Recall@1, Recall@3, Recall@5와 정확 조문 적중률을 기록한다. `key_facts`는 생성 답변의 사실 누락과 부정확한 단정 여부를 수동 점검하는 체크리스트로 사용한다. 공개 10문항에 과적합하지 않도록 모든 규칙은 약관의 계층·시행일·인용 계약에서만 도출한다.

## Git 동기화 안전 규칙

스크립트는 현재 브랜치가 upstream을 가진 Git 저장소인지 확인하고, 미커밋 변경이 있으면 중단한다. 이후 `git fetch --prune origin`과 `git pull --ff-only`만 수행한다. 자동 rebase, 강제 push, reset, stash는 수행하지 않는다. fast-forward가 불가능하면 원인을 설명하고 사용자가 직접 병합 또는 rebase를 선택하도록 한다.

## 검증

- 두 Markdown 문서에 모든 대상 약관, 공개 평가셋, T4 제약, 검색·저장·평가 근거가 포함되는지 확인한다.
- 스크립트는 `zsh -n`으로 구문을 검사한다.
- 깨끗한 작업 트리, 변경된 작업 트리, upstream 없는 브랜치의 세 경우를 코드 경로로 점검한다.
